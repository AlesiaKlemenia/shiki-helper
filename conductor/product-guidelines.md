# Product Guidelines: Shiki-Helper

## Communication Style

- **Язык**: Русский — основной язык интерфейса бота и документации.
- **Тон**: Лаконичный, профессиональный, дружелюбный. Без излишних слов — только суть.
- **Эмодзи**: Умеренно, для обозначения статусов (🟢 онлайн, 🔴 ошибка, 📺 новая серия, ⏰ расписание).

## UX Principles

1. **Минимум шагов**: Онбординг — максимум 4 шага с прогресс-баром в диалоге.
2. **Понятные ошибки**: При ошибках Google OAuth или Shikimori API — человекочитаемое сообщение с инструкцией, что делать.
3. **Graceful Degradation**: Если Redis недоступен — бот продолжает работу на MemoryStorage с предупреждением.
4. **Подтверждения**: Деструктивные действия (удаление тайтлов, отвязка аккаунта) — всегда с запросом подтверждения.
5. **Состояние видно**: Пользователь всегда может проверить текущий статус подключений и следующее время рассылки.

## Message Formatting

- Дайджест: чёткая структура — заголовок, список тайтлов с эмодзи 📺, количество серий, ссылка на Shikimori.
- Ошибки авторизации Google: кнопка «Переавторизоваться» прямо в сообщении.
- Уведомления о восстановлении: `🟢 Бот успешно запущен и восстановил соединение с базой данных`.

## Code Quality

- Все публичные функции — с docstrings (Args, Returns, Raises).
- Типовые аннотации обязательны (`from __future__ import annotations`).
- Логирование через structlog / logging с контекстом (user_id, operation).
- Никаких голых `except` — только конкретные типы исключений.
- Секреты только из переменных окружения, никогда в коде.
